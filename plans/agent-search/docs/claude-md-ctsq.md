# Code Search Tools
- prefer semble (/semble) over grep for semantic code search
- prefer ctsq over grep, sed, cat, head or tail for anything in source files (.c .cpp .h .py .js .ts .rs .go .rb). A PreToolUse hook denies those shell readers on source paths. Use Read only when you need a whole file. One call per question, then the next call:
  - what is this symbol or what does it do (start here): `ctsq explain Name src/` gives the body, callers, callees and other uses in one call
  - show a definition: `ctsq -q '*function#Name' --body src/`. Several at once: `ctsq -q '*function#/^(A|B)$/' --body src/`. `*type#` and `*variable#` (alias `*const#`) work the same
  - where is a name used: `ctsq -q 'id#Name' src/` prints `path:LINE: source line`. Add `-C 3` for context lines, then pull the caller with `--body`
  - where does some text appear: `ctsq -q 'literal#/some text/' src/`. `id#` only matches identifiers, so a string needs `literal#`. An `id#` that matches nothing is rerun over strings and comments and ends with a `try:` line, run it. A `/` inside a regex filter is written `\/`
  - what is in a file: `ctsq tree file.rs` for the outline and size, then `ctsq -q '*function#name' --body file.rs` for one body
  - who calls it: `ctsq callers Name src/`, then `ctsq explain` on a caller. Also `callees` and `callgraph`
  - where is a method called: `ctsq -q 'call#Name' src/` matches the last segment, so `pkg.Name(...)` and `x.Name(...)` both hit. `comment#/text/` finds comments. Scripts with no extension are read by their shebang, no `--lang` needed
  - what function or class holds a hit: add `--scope` to `def`, `refs`, `callers`, `callees`, `files` or `-q`. A row under each hit gives the holder's `path:START-END` and signature, so no window Read follows. `--scope --body` adds the holder's body
  - what holds this file:line (from a stack trace, a compiler error or grep): `ctsq scopeof path:LINE`, the reverse of `def`. It returns the function or class with its body, no window Read needed. `--up 1` for the class, `--siblings`, `--callers`, `--budget N`
  - files where several names occur: `ctsq files -q 'id#A' -q 'id#B' src/`
  - where UI text, a label, a route or a logged error message lives: `ctsq find text 'Welcome back'`, `ctsq find label`, `ctsq find route /path` and `ctsq find error 'the message as logged'` name the component or function that holds it, and `find error` reads %s and %w in the code as wildcards. A repo `.ctsq/glossary.toml` maps product words to code names for `find`, `def` and misses
  - which component serves a route, or another framework question: `ctsq find` lists the named queries that apply in this directory, then `ctsq find route /path` prints each route's `path:LINE`, key, component and its definition. A miss names the query file, override it in `.ctsq/queries/`
  - where is it defined: `ctsq def Name src/`, or several at once: `ctsq def A B C src/` (a miss is named on stderr, exit 0 if any resolved). Functions that use a constant: `ctsq -q '(*function @f).body(id#CONST)' file.cpp`
  - tests are hidden by default and counted on the last line, `hidden: N in tests (--tests)`. Before deleting or renaming a name, rerun with `--tests` to see every use. `--exclude GLOB` hides more paths
  - restrict by language with `-l cpp`. Unsure of the query syntax: `ctsq example '$X.send(msg)' -l js`
- prefer mdq over cat/sed/grep for any markdown file (.md): run `mdq tree` first, then `mdq section` for the part you need, never read a markdown file whole to find one section:
  - `mdq tree file.md`                        replaces `cat file.md` / `head -100 file.md`
  - `mdq toc file.md`                         replaces `grep -n '^#' file.md`
  - `mdq section file.md 'Heading'`           replaces `grep -n '^## Heading' file.md` then `sed -n '42,180p' file.md`
  - `mdq section file.md 'A' 'B' 'C'`         several sections in one call, use this instead of three calls
  - `mdq section file.md 'Heading' --no-body` outline of one section, prose left out. A bare number is a line number
  - `mdq grep docs/ 'A|B'`                    replaces `grep -rn 'A\|B' docs/`, each hit tagged with its section. Alternation is `A|B`, not `A\|B`
  - `mdq tasks todo.md`                       replaces `grep -n '\- \[ \]' todo.md` (open items only by default)
  - `mdq tasks Projects.md --section Doing --tag mavexa --all`  filter a kanban or todo list without reading it
  - heading match ignores case, leading #s, emoji and trailing status text. A unique prefix or `/regex/` works. Several matches list candidates and exit 2, no match names the closest headings
- Read tool:
  - read a file whole when it is under about 1,000 lines, never in windows. Three windowed Reads cost three turns and save nothing
  - over about 1,000 lines the Read tool caps the first call. If you are about to edit that file, page forward from where the cap stopped in contiguous windows, each starting at the previous end, never re-reading a range. If you are not editing it, do not page, use `ctsq -q 'id#X' -C 5` or `ctsq -q '*function#Name' --body` for the part you need
  - never pass `limit` unless you actually want a slice, and never Read a window around a ctsq hit, add `-C N` to the ctsq call instead
- prefer LSP over Read | Grep for code navigation
